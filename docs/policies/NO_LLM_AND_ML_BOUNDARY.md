# No-LLM and Permitted Machine-Learning Boundary

## Prohibited authority

A large language model or equivalent generative foundation model must
not become Forge 2.0's authoritative component for:

- request meaning selection;
- tool selection;
- planning;
- shell authorization;
- code correctness;
- truth judgment;
- permission;
- memory promotion;
- economic finalization;
- deployment approval.

## Permitted bounded models

Forge 2.0 may use small purpose-specific models for candidate generation,
classification, ranking, anomaly detection, and retrieval assistance.

Candidate model families include:

- logistic regression;
- linear support-vector machines;
- naive Bayes;
- decision trees;
- random forests;
- gradient-boosted trees;
- conditional random fields;
- hidden Markov models;
- classical clustering;
- bounded purpose-specific neural classifiers.

## Execution boundary

A model produces a typed candidate set.

A model does not receive unrestricted terminal, filesystem, network,
Git, package, memory, economic, or deployment authority.

Authority is evaluated separately by policy and execution services.

## Governance

Every promoted model version requires a dataset manifest, feature
specification, metrics, error analysis, artifact hash, predecessor,
promotion receipt, and rollback.
