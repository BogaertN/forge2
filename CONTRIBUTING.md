# Contributing to AI.Web Forge 2.0

Forge 2.0 is built through bounded, evidence-backed production changes.

## Required contribution sequence

1. Identify the controlling roadmap phase and build.
2. Record the objective, scope, non-goals, and protected boundaries.
3. Inspect existing local and open-source capabilities first.
4. Create or update typed contracts before adding hidden data fields.
5. Work on a dedicated branch or isolated worktree.
6. Add tests for the declared behavior and failure boundaries.
7. Run independent verification.
8. Review source scope, dependencies, licensing, security, and rollback.
9. Commit one coherent verified change.
10. Preserve provenance and contribution evidence.

## Prohibited contribution patterns

- Direct experiments in the protected primary worktree
- Hidden large-language-model authority
- Raw unrestricted shell execution
- Unqualified package installation
- Question-specific canned answers presented as intelligence
- Silent mutation
- Silent fallback
- Tests that prove only fixtures while claiming general behavior
- Deleting failure evidence to make a build appear successful
- Importing Forge 1 as a runtime dependency

## Open-source-first requirement

Original implementation is the last option. Contributions must explain
why registered, installed, donor, open-source, configurable, composable,
or adaptable capabilities were not sufficient.
